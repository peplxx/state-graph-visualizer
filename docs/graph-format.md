# Формат YAML для графов состояний

Документ описывает YAML-формат для визуализации графов состояний в задачах планирования реального времени.

## Быстрый пример

```yaml
schemaVersion: 1

system:
  description: "EDF граф достижимости – τ₁=(2,5) τ₂=(3,7) m=1"
  m: 1
  tasks:
    - { c: 2, d: 5, name: "τ₁" }
    - { c: 3, d: 7, name: "τ₂" }

nodes:
  - id: n00
    initial: true
    tasks:
      - { c: 0, d: 0 }
      - { c: 0, d: 0 }
    children: [n10, n11]

  - id: n10
    tasks:
      - { c: 2, d: 5, release: up }
      - { c: 0, d: 0 }
    children: [n20]

  - id: n20
    tasks:
      - { c: 0, d: 3, release: down }
      - { c: 0, d: 0 }
    loopback: [n00]

layout:
  algorithm: dagre
```

## Поля верхнего уровня

| Поле | Обязательно | Описание |
|------|-------------|----------|
| `schemaVersion` | рекомендуется | Версия формата (по умолчанию `1`) |
| `system` | нет | Метаданные системы планирования |
| `nodes` | **да** | Список состояний графа (минимум одно) |
| `layout` | нет | Настройки визуализации |

## `system`

| Поле | Тип | Описание |
|------|-----|----------|
| `description` | string | Описание графа в свободной форме |
| `m` | number | Количество процессоров |
| `tasks` | array | Параметры задач: `{ c, d, name? }` |

`c` — максимальное время выполнения (WCET), `d` — относительный дедлайн.

## `nodes[]`

Каждый узел — глобальное состояние системы.

| Поле | Тип | По умолчанию | Описание |
|------|-----|--------------|----------|
| `id` | string | — | Уникальный идентификатор узла |
| `initial` | boolean | `false` | Начальное состояние (жирная граница) |
| `tasks` | array | `[]` | Состояние каждой задачи в этом узле |
| `children` | string[] | `[]` | Переходы состояний (сплошные рёбра) |
| `loopback` | string[] | `[]` | Дуги высвобождения задач (красные пунктирные) |
| `label` | string | авто | Переопределить отображаемую метку узла |
| `borderColor` | CSS-цвет | тема | Цвет границы узла (опционально) |
| `fillColor` | CSS-цвет | `#FFFFFF` | Цвет заливки узла (опционально) |
| `metadata` | object | — | Произвольные метаданные для инструментов |

Рёбра **не задаются напрямую** — они синтезируются из `children` (переходы состояний) и `loopback` (дуги высвобождения).

### Пример с цветами

```yaml
- id: n10
  tasks:
    - { c: 2, d: 5, release: up }
  borderColor: "#2E86AB"
  fillColor: "#E8F4F8"
  children: [n20]
  loopback: [n00]
```

### `tasks[]` внутри узла

| Поле | Тип | По умолчанию | Описание |
|------|-----|--------------|----------|
| `c` | number | `0` | Оставшееся время вычисления |
| `d` | number | `0` | Относительный дедлайн текущего задания |
| `release` | `up` \| `down` \| `none` | `none` | Событие высвобождения задания |

Псевдонимы, которые принимает парсер: `↑` и `1` → `up`, `↓` и `-1` → `down`.

| Значение | Символ | Смысл |
|----------|--------|-------|
| `up` | ↑ | Задание высвобождено |
| `down` | ↓ | Задание завершается |
| `none` | — | Нет события высвобождения |

## `layout`

```yaml
layout:
  algorithm: dagre       # иерархический (сверху вниз)
  # algorithm: concentric  # кольцевой (начальный в центре)
```

| Алгоритм | Описание |
|----------|----------|
| `dagre` | Иерархическая укладка DAG (по умолчанию) |
| `concentric` | Кольцевая укладка: начальный узел в центре, каждый переход `children` добавляет кольцо |

## Схема и валидация

Формат определён в [`src/schema/graphSchema.ts`](../src/schema/graphSchema.ts) через Zod.

### Сгенерировать JSON Schema

```bash
bun run schema:generate
```

Записывает [`schema/graph-v1.schema.json`](../schema/graph-v1.schema.json). Используется с расширением YAML в VS Code и другими инструментами, поддерживающими JSON Schema.

### Проверить YAML-файл

```bash
bun run schema:validate
bun run schema:validate examples/gfp-m1-1-2-1-2.yaml
```

Запускает JSON Schema-валидацию (AJV) + Zod-проверки на уровне графа: дубликаты `id`, несуществующие ссылки в `children`/`loopback`, несоответствие числа задач.

### Синхронизировать схему

```bash
bun run schema:check
```

Перегенерирует JSON Schema и падает, если закоммиченный файл не совпадает (используется в CI).

## Примеры

Графы сгенерированы GFP-генератором libstgx без отсечения состояний. Пары задают `(c, d)`, порядок задач определяет фиксированный приоритет (первая — высший).

- [`gfp-m1-1-2-1-2.yaml`](../examples/gfp-m1-1-2-1-2.yaml) — `m = 1`, задачи `(1, 2), (1, 2)`; 9 состояний.
- [`gfp-m1-2-5-3-7.yaml`](../examples/gfp-m1-2-5-3-7.yaml) — `m = 1`, задачи `(2, 5), (3, 7)`; 48 состояний.
- [`gfp-m2-1-2-2-3-3-4.yaml`](../examples/gfp-m2-1-2-2-3-3-4.yaml) — `m = 2`, задачи `(1, 2), (2, 3), (3, 4)`; 81 состояние, из них 5 с нарушением дедлайна.

Кратко о генерации — в [`examples/README.md`](../examples/README.md).
